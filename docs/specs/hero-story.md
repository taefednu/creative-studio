# «Оживи рисунок» и сказка на 4 страницы

Решение 02.11.2026, причина и проба: project notes. Рубрика хакатона: «Use of Meta AI Tooling, удивили нас?» 25 %, демо 25 %.
Проба `edit_image`: герой один и тот же на всех 4 страницах, каждая 15–26 с; фото каракуль на мятой бумаге оживает с сохранением кривых лап.

## Поведение

1. Ребёнок загружает фото рисунка (поток уже есть). На готовой загрузке главная кнопка «Оживи», 1 монета.
2. Новая работа `kind="alive"`: Muse Image `edit_image` по файлу загрузки, рисунок ребёнка становится 3D-героем, форма и цвета рисунка сохраняются. Дальше как обычная картинка: проверка, готово, можно показать классу.
3. На готовом герое кнопка «Сочини сказку», поле для идеи необязательное (текст или голос), цена `STORY_PRICE`, 3 монеты.
4. Muse Spark пишет сказку на языке ребёнка, строгий JSON: название и 4 страницы (1–2 простые фразы и описание сцены на английском). Muse Image рисует 4 сцены `edit_image` по герою, параллельно.
5. Страницы появляются по мере готовности. Готовую книжку можно показать в ленте; у одноклассника карточка открывается как книжка.

## Что нельзя нарушить

Каждая строка ниже проверяется тестом.

- Детское неразмытое фото не уходит в модель и другому человеку. Источник оживления только `file_path` своей готовой загрузки (размытый файл), никогда оригинал `orig/`. Тест сверяет байты, переданные в `edit_image`.
- Небезопасная сказка не доходит до ребёнка. Идея проверяется `check_text` до генерации. Каждая страница и название проверяются `check_text`, каждая картинка `check_image`, до показа. Страница видна, только когда её текст и картинка прошли.
- Сбой или невалидный ответ проверки, «не allow» по странице: вся сказка `held`, очередь взрослого (`item_type="story"`), ребёнок страниц не видит, в том числе уже показанные. Ответ тревожный (`support`, urgent): только тёплый ответ, как у `prompt`, очередь `both`.
- Сбой генерации (таймаут, 4xx/5xx, битый JSON от Muse Spark после одной повторной попытки) не оставляет ребёнка без монет: возврат один раз, статус `failed`. Текст ребёнка идёт в промпт только в ограждении (`safety/prompts.py`).
- Двойной клик: тот же `request_id` возвращает ту же сказку и не списывает второй раз (`UniqueConstraint`, как у `Work`).
- Чужой ребёнок, гость, чужой родитель: 404 на сказку и на картинку страницы. Опубликованную страницу читатель видит только через проверку доступа поста (`service.access`).
- Перезапуск процесса: `recover_stuck` переводит незавершённые сказки в `failed` с возвратом.
- Без взрослого нельзя: зависимость `child_with_adult`, как у ремикса.
- ID моделей и ключи только из настроек.

## Как устроено (минимум новых сущностей)

- `Work`: новое поле `hero_of_work_id` (FK works.id, nullable); `kind="alive"`, `template_id="alive"`. В `pipeline._run` источник читается рядом с ремиксом; для `alive` проверки текста нет (текста нет), промпт постоянный. `POST /api/works/{id}/alive {request_id}`: 404, если работа чужая, не `upload` или не `ready`.
- Новая таблица `Story` в `app/works/story/`: `child_id`, `hero_work_id`, `cover_work_id` (nullable), `request_id`, `idea`, `lang`, `status` (`checking`, `writing`, `drawing`, `ready`, `held`, `refused`, `support`, `failed`), `title`, `pages` JSON `[{text, scene, file, ok}]`, `reason_codes`, `created_at`. Файлы страниц в `UPLOAD_DIR`.
- Источник героя: своя `ready`-работа с картинкой (`alive` или `image`).
- `POST /api/stories {hero_work_id, idea?, request_id}`, `GET /api/stories/{id}` (страницы с `ok`, `image_url` только у них), `GET /api/stories/{id}/pages/{n}/image`, `GET /api/stories/mine`. Сбой и отказ по образцу `pipeline`: монета и статус одним коммитом. Цена в `GET /api/templates` как `story_price`.
- Публикация без новых ручек: готовая сказка создаёт обложку `Work(kind="page", status="ready", file_path=страница 1)`, её id в `Story.cover_work_id`; клиент публикует через существующий `POST /api/posts`. В `_views` поста поле `story: {id, title, pages: [{text}]} | null`; картинка страницы читателю: `GET /api/posts/{id}/story/{n}` через `_get_post`. Пост сказки без ремикса (`can_remix=false`).
- `register("story", approve, reject)`: одобрение делает `ready` и открывает страницы, отклонение `refused`.
- Схема без миграций (`create_all`): стенд пересоздаётся.
