# evals — размеченный набор безопасности

Измеряем, как проверка ловит небезопасное. Сами данные сюда пока не добавлены; сырое и детское
не коммитим (`data/raw/` в `.gitignore`).

## Формат записи

Один пример — одна строка JSONL в `evals/sets/<тип>.jsonl`, типы: `prompts`, `posts`, `comments`.

```json
{"id": "c-0001", "type": "comment", "lang": "uz", "text": "...", "labels": ["personal_info"], "expected_action": "hold"}
```

| Поле | Значение |
|------|----------|
| `id` | уникальный, префикс типа |
| `type` | `prompt` / `post` / `comment` |
| `lang` | `ru` / `en` / `uz` |
| `text` | текст примера (для постов — описание или ссылка на файл вне git) |
| `labels` | список категорий безопасности; пустой список — безопасный пример |
| `expected_action` | `allow` / `rewrite` / `hold` |

Категории (первый список, [TBD] до `/grilling`): `personal_info`, `off_platform_contact`, `bullying`,
`unsafe_content`, `sensitive_image_data` (лица, форма, номера домов, написанные имена).

## Метрики

Для каждой категории и каждого языка отдельно:

- precision = TP / (TP + FP), recall = TP / (TP + FN), где положительный класс — «категория есть».
- Для безопасности главный показатель recall: пропущенное небезопасное хуже лишней задержки. Итог
  показываем таблицей «категория x язык» с числом примеров, чтобы малые выборки были видны.
- Слепой прогон: промпты модели не правятся по примерам тестового набора; набор делится на dev и test.

Скрипт: `python -m evals.run` (будет в `backend/`, [TBD]).
