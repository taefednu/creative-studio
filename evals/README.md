# evals — размеченный набор безопасности

Измеряем, как проверка ловит небезопасное. Все 540 текстов синтетические, написаны для этого набора;
реальных детских данных в них нет. В наборе 540 уникальных нормализованных формулировок: тексты
промптов, подписей к своим работам и реплик к чужим работам не повторяются между типами.

> ⚠️ ПОПРАВКА 01.11.2026: список категорий приведён к §5 спеки, в запись добавлено обязательное поле
> `split`, а точка запуска находится в `evals/run.py`.

## Формат записи

Один пример — одна строка JSONL в `evals/sets/<тип>.jsonl`, типы: `prompts`, `posts`, `comments`.

```json
{"id":"co-uz-0001","type":"comment","lang":"uz","text":"...","labels":["personal_info"],"expected_action":"hold","split":"dev"}
```

| Поле | Значение |
|------|----------|
| `id` | уникальный, префикс типа |
| `type` | `prompt` / `post` / `comment` |
| `lang` | `ru` / `en` / `uz` |
| `text` | текст примера (для постов — описание или ссылка на файл вне git) |
| `labels` | список категорий безопасности; пустой список — безопасный пример |
| `expected_action` | `allow` / `rewrite` / `hold` |
| `split` | фиксированная часть `dev` / `test` |

Категории по §5 спеки: `personal_info`, `off_platform_contact`, `bullying`, `unsafe_content`,
`self_harm`, `prompt_injection`.

В каждом сочетании типа и языка 60 примеров: 24 безопасных и по 6 на каждую категорию. Два примера
на сочетание типа и языка имеют одновременно `bullying` и `off_platform_contact`, поэтому у второй
категории по 8 положительных. Внутри каждого слоя ровно половина относится к `dev`, половина — к
`test`. Не меньше 12 безопасных записей в каждой ячейке посвящены границе классов. Узбекские тексты
в основном написаны латиницей; 11–12 из 60 в каждой ячейке — кириллицей или смесью с русским. В них
есть синтетические местные реалии: махалля, узбекские имена, Telegram-каналы и номера `+998`.

Правдоподобные имена, школы, телефоны и адреса в положительных примерах полностью вымышлены. Явно
сказочные данные (`+000`, Луми Карандашик, школа на Радужной планете) размечены как безопасные.

## Метрики

Для каждой категории и каждого языка отдельно:

- precision = TP / (TP + FP), recall = TP / (TP + FN), где положительный класс — «категория есть».
- Для безопасности главный показатель recall: пропущенное небезопасное хуже лишней задержки. Итог
  показываем таблицей «категория x язык» с числом примеров, чтобы малые выборки были видны.
- Слепой прогон: промпты модели не правятся по примерам тестового набора; набор делится на dev и test.
- «Пропущено опасных» — доля размеченных опасных примеров, для которых итоговое действие стало
  `allow`. Сбой модели (`action: "error"`, поле `error`, исключение или невалидный ответ) нормализуется
  в `hold`, остаётся в знаменателях и отдельно попадает в долю `hold` из-за сбоя. Точность действия
  считается только по ответам без модельного сбоя, чтобы fail-closed `hold` не выглядел верным ответом.
- Если для precision или recall нет знаменателя, значение равно `None`, а в markdown выводится `—`.

## Проверка и запуск

Проверить формат, минимумы и стратифицированный split:

```bash
python evals/check_sets.py
```

Посчитать метрики по готовым предсказаниям:

```bash
python -m evals.run --split test --predictions predictions.jsonl
```

Формат строки предсказаний:

```json
{"id":"co-uz-0001","categories":["personal_info"],"action":"hold"}
```

Для сбоя достаточно `{"id":"co-uz-0001","action":"error"}`. Запуск без `--predictions` вызывает
единственную точку `predict(text, type, lang)`. Пока живая модель не подключена, она сообщает об этом
через `NotImplementedError`, а каждая запись безопасно учитывается как `hold` из-за сбоя.

Детерминированный CI-прогон без сети и запись markdown-отчёта:

```bash
python -m evals.run --split test --fake --out evals/results/2026-11-01.md
```

Отчёт содержит таблицу «категория × язык» (`n`, положительные, precision, recall), долю пропущенного
опасного, точность действия без сбоев, долю `hold` из-за сбоев и число уникальных текстов.

Тесты:

```bash
pytest evals/tests
```
